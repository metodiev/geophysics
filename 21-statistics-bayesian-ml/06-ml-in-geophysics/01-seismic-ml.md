# ML for Seismic Detection, Picking and Classification

## Learning objectives

By the end of this lesson you will be able to:

1. **Define** the three seismic ML tasks — detection, phase picking and
   classification — and state the label each one actually requires.
2. **Construct** a feature vector for a short window from a time-domain
   trigger ratio, a shape statistic and a spectral ratio, and say what each
   feature measures in the presence of noise.
3. **Compute** the true- and false-positive rates of a single-feature trigger
   from a labelled window population, and **explain** why one threshold trades
   one against the other.
4. **Compare** a learned classifier with a classical trigger at equal
   false-positive budgets, and **state** which comparison is meaningful.
5. **Interpret** an AUC as a threshold-free ranking summary, and **identify**
   the three numbers a deployed detector must report instead.
6. **Choose** an evaluation protocol (class balance, low-FPR operating point,
   station- and time-disjoint splits) and **diagnose** the leakage that a random
   window split introduces.
7. **State** the assumptions under which detection performance measured on
   synthetic windows transfers to a real network, and list what it does not
   constrain.

The window population, the wavelet and every rate quoted below are **SYNTHETIC**.
They are generated by the demonstration in
[`code/seismic_ml_demo.py`](./code/seismic_ml_demo.py); no recording, catalogue
or published detection curve is used anywhere in this lesson.

## 1. Intuition: a detector is a decision rule, not a model

Everything downstream in observational seismology depends on one binary decision
made thousands of times per station per day: *is there an event in this window?*
The classical answer is a **short-term average to long-term average (STA/LTA)
ratio** compared with a fixed number. The modern answer is a **learned
classifier** whose input is a vector of features, or the raw waveform.

Both are decision rules. The difference is not "statistics versus AI"; it is
that the classical rule uses one hand-chosen statistic and one hand-chosen
threshold, while the learned rule uses many statistics and a threshold that is
still chosen by a human. This lesson keeps that symmetry visible by measuring
both on the *same* synthetic windows and reporting the operating point of each.

A decision rule is fully described by three numbers at a stated operating point:
the **true-positive rate** (TPR, the fraction of events retained), the
**false-positive rate** (FPR, the fraction of noise windows that fire), and the
**threshold**. An AUC is none of those, and a detector that is deployed is
always a triple.

## 2. The synthetic population

The demonstration builds 600 windows of 200 samples at 100 Hz (2.0 s each). Half
contain a single 8 Hz Ricker wavelet whose peak amplitude is 3.0 times the RMS
of the Gaussian noise in that same window; the onset is placed uniformly between
0.6 s and 1.4 s. Half contain noise only. Four features are computed per window:

| Feature | Symbol | Unit | What it measures |
|---|---|---|---|
| logarithm of the peak STA/LTA ratio | $\log_{10}\rho_{\max}$ | dimensionless (log of a ratio) | transient versus background energy |
| logarithm of the window kurtosis | $\log_{10}\kappa$ | dimensionless | peakedness: an event makes the histogram spikier |
| logarithm of the 4–12 Hz to 0.5–2 Hz energy ratio | $\log_{10}E_{\mathrm{hi}}/E_{\mathrm{lo}}$ | dimensionless | spectral content, not amplitude |
| peak amplitude over RMS | $A_{\mathrm{pk}}/\sigma$ | dimensionless | the classical signal-to-noise proxy |

The medians of these features over the training windows are

| Feature | noise-only median | event median |
|---|---|---|
| $\log_{10}\rho_{\max}$ | $+0.289$ | $+0.394$ |
| $\log_{10}\kappa$ | $+0.461$ | $+0.538$ |
| $\log_{10}E_{\mathrm{hi}}/E_{\mathrm{lo}}$ | $+0.671$ | $+0.935$ |
| $A_{\mathrm{pk}}/\sigma$ | $2.903$ | $3.412$ |

No single feature separates the classes. The peak-to-RMS ratio — the statistic
most people reach for first — moves from 2.90 to 3.41, because the event occupies
only about 0.25 s of a 2.0 s window. That is the quantitative reason a
multi-feature classifier can beat any single trigger.

## 3. The classical trigger and its operating point

The demonstration applies the usual field default, a ratio threshold of 2.0, to
the held-out 200 windows and measures

$$\text{TPR} = 0.880, \qquad \text{FPR} = 0.390, \qquad
\text{accuracy} = 0.745 \ \text{(classes balanced)}.$$

An FPR of 0.390 is not a defect of the implementation; it is what a threshold of
2.0 buys on windows with this signal-to-noise ratio. If instead the threshold is
calibrated *on the training noise windows* so that 5% of them fire, the ratio
becomes 2.66, and the measured test performance is

$$\text{FPR} = 0.090, \qquad \text{TPR} = 0.280 .$$

The two operating points sit on the same curve: lowering the threshold to gain
events also admits noise. Nothing about the trigger is wrong; the useful
question is which point the application can afford, and that is a decision about
the cost of a false alarm and a missed event, not a property of the data.

## 4. What a learned classifier adds

A logistic regression on the four standardised features, fitted on 400 windows
and tested on 200, gives standardised coefficients

$$+1.08\ (\log_{10}\rho_{\max}),\quad +0.88\ (\log_{10}\kappa),\quad
+1.10\ (\log_{10}E_{\mathrm{hi}}/E_{\mathrm{lo}}),\quad
+0.40\ (A_{\mathrm{pk}}/\sigma),$$

that is, it weights the spectral ratio and the trigger ratio about equally and
uses all four features positively. Measured on the same 200 held-out windows:

| Quantity | Value |
|---|---|
| test accuracy at probability 0.5 | 0.815 |
| TPR at probability 0.5 | 0.770 |
| FPR at probability 0.5 | 0.140 |
| test AUC | 0.891 |
| score at the 95th percentile of training noise | 0.773 |

The learned classifier is better, but the honest comparison is at equal
false-positive budget. Calibrating the learned score on the training noise
windows gives

| False-positive budget | threshold | measured test FPR | measured test TPR |
|---|---|---|---|
| 5% | 0.773 | 0.040 | 0.560 |
| 1% | 0.886 | 0.020 | 0.340 |

Against the trigger at the same 5% budget (calibrated threshold 2.66, test TPR
0.280) the learned classifier roughly doubles the retained events. That is the
result worth quoting: **+0.28 in TPR at a fixed 5% false-positive rate**, not an
AUC difference.

## 5. Detection, picking and classification are different label problems

The three tasks in the title are often conflated because one network can be
asked to do all three.

- **Detection** needs a binary label per window: event or noise. The label is
  cheap (a catalogue gives it), and a missed small event is invisible.
- **Picking** needs a *continuous* label per record: the arrival time, to within
  a stated tolerance. A window label is not enough, and
  [21-06-02](./02-phase-picking-ml.md) shows the measured consequence: a picker
  trained on window labels carries a systematic bias of $-0.180\ \mathrm{s}$.
- **Classification** (explosion versus earthquake, local versus regional) needs a
  label per *event*, which is usually the expensive one, and it inherits every
  error made by the detector and the picker upstream.

The label determines what the model can learn. A binary window label can never
teach sub-window timing, no matter how large the network.

## 6. Evaluation that does not lie

Three failure modes dominate published seismic-ML evaluation.

1. **A class-balanced test set is not the field.** With 300 events among 600
   windows the prior is 0.5. At a real station the event prior may be $10^{-3}$,
   and at a fixed FPR of 0.140 the precision becomes
   $0.770 \times 10^{-3} / (0.770\times10^{-3} + 0.140\times0.999) = 0.0055$ —
   about one true detection per 180 triggers. Report the prior with the rates.
2. **Random window splits leak.** Overlapping or adjacent windows from the same
   event appear in both folds. Splits must be **disjoint in event and in time**
   (and ideally in station), or the reported AUC is an optimism of unknown size.
3. **The test set is small.** The demonstration's 200 held-out windows contain
   100 events, so one event is 1.0% of the TPR: a difference of two events is
   noise. Quote a binomial interval, not three decimals.

## 7. Assumptions and regime of validity

1. **The noise is Gaussian and stationary.** Real station noise is coloured,
   has cultural transients, and its spectrum changes between day and night. A
   classifier trained on white noise has no reason to transfer.
2. **The event is a single wavelet of known frequency.** A Ricker wavelet at
   8 Hz is not a P onset, an S onset, a regional Lg or a microseism; each has a
   different feature signature.
3. **The amplitude is known exactly up to a constant.** Real amplitudes carry
   geometric spreading, site response, instrument response and attenuation.
4. **Every window is independent.** Consecutive windows overlap in practice, so
   the counts are not independent and the binomial intervals of §6 are, strictly,
   too narrow.
5. **The label is perfect.** Catalogue labels are themselves detections. If the
   training labels came from a trigger, the classifier learns that trigger's
   blind spots as truth.

## The honest summary

A learned classifier over four interpretable features raised the retained events
at a 5% false-positive budget from $0.280$ to $0.560$ TPR on a synthetic
window population whose noise is white and whose events are one 8 Hz wavelet.
That is a real gain in a controlled setting and it says nothing about a field
network. The numbers that transfer are the ones reported as a
(threshold, FPR, TPR) triple with the event prior attached; the number that does
not transfer is the AUC. The upstream error budget of any catalogue is set by
these decisions, so the detector's operating point belongs in the methods
section of any study that uses its output.

## Mastery checkpoint

Without notes:

1. At a 5% false-positive budget the learned classifier retains 0.560 of the
   events and the trigger retains 0.280. Convert both to the number of events
   expected per 1000 triggers if the event prior is $10^{-3}$, assuming the
   measured rates hold at that prior.
2. State the three numbers a published detector must report, and explain in one
   sentence why an AUC cannot be converted into any of them.
3. Your colleague trains a detector on overlapping 2 s windows and reports 0.98
   AUC from a random split. Name the two leaks and the split you would demand.
4. The event peak-to-RMS ratio in this population moves from 2.90 to 3.41, yet
   the classifier reaches 0.891 AUC. Explain the difference in one paragraph
   using the word "feature".

## Common pitfalls

1. **Reporting accuracy on a balanced synthetic set.** The demonstration's 0.815
   accuracy belongs to a 50/50 prior; at a field prior the same rule is almost
   all false positives.
2. **Quoting an AUC as if it were a detection rate.** The AUC of 0.891 is
   compatible with a 0.340 TPR at a 1% budget.
3. **Comparing a learned model with an uncalibrated trigger.** The trigger at
   ratio 2.0 has FPR 0.390; the comparison is only meaningful at equal budget.
4. **Using window labels to claim timing accuracy.** Window labels cannot
   resolve sub-window arrival times; see
   [21-06-02](./02-phase-picking-ml.md) for the measured bias.
5. **Splitting randomly when windows overlap.** Adjacent windows share the same
   event; the test fold is then not independent.
6. **Forgetting the number of test events.** 100 events means the TPR moves in
   steps of 0.01, and two events of difference is noise.

## Where this is used

- Routine and induced-seismicity monitoring, where a detector's false-alarm rate
  sets the operating cost of a traffic-light protocol
  ([06-12-04](../../06-seismology/12-induced-and-triggered-seismicity/04-monitoring-and-mitigation.md)).
- Aftershock-sequence studies, where a fixed detection threshold during the
  coda biases the $b$-value of
  [06-11-01](../../06-seismology/11-earthquake-statistics-and-hazard/01-gutenberg-richter.md).
- Discrimination of explosions from earthquakes, a *classification* task whose
  label is per event and whose errors are dominated upstream.
- Microseismic monitoring of reservoirs, where the event prior is low and the
  false-positive budget therefore dominates the design.
