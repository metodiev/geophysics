# Exercises — 22-01-01 Designing Software for Scientific Research

Attempt these before reading the
[solutions](./01-software-design-science-solutions.md). The lesson is
[01 Designing Software for Scientific Research](../01-software-design-science.md).
All graph numbers refer to the **SYNTHETIC** package generated by
`code/software_design_science_demo.py` (60 modules, 101 edges).

## ★ Foundational

**★1.** The demonstration reports 60 modules and 101 dependency edges.

(a) Compute the edge density: the number of realised edges divided by the number
of possible ordered pairs of distinct modules. (b) Compute the mean fan-out in
two ways and show the results agree. (c) Explain in one sentence why the mean
fan-in must equal the mean fan-out on any dependency graph.

**★2.** Compute the instability $I = \text{fan-out}/(\text{fan-in}+\text{fan-out})$
for each module and state which you would expect to change most often:

- module A: fan-in 8, fan-out 2;
- module B: fan-in 0, fan-out 5;
- module C: fan-in 0, fan-out 0.

**★3.** For the small directed graph $D \to A$, $A \to B$, $B \to C$, $A \to C$,
compute the blast radius (number of modules that can reach it) of each of
$A$, $B$ and $C$. State which module is the worst single point of change.

## ★★ Applied

**★★4.** Use the demonstration's defect model,
density $= 0.50 + 0.30 \times (1 + \text{fan-out} + \text{fan-in})$ defects per
KLOC, to compute the modelled density of a module with fan-in 8 and fan-out 2.
Compare it with the demonstration's mean density on high-blast modules ($2.45$
per KLOC) and with the package mean ($1.81$ per KLOC). State one reason the
single-module value can exceed the group mean.

**★★5.** The following function is used in an analysis script:

```python
def run(cfg):
    data = np.loadtxt(cfg["path"])
    out = np.diff(data, axis=0) / cfg["dt"]
    plt.plot(out)
    plt.savefig(cfg["fig"])
    return out.mean()
```

Rewrite it as a boundary between computation and surroundings: give the pure
core a narrow signature, and name the one place each side effect belongs. Then
state the single test that the original could not pass and the rewrite can.

**★★6.** The demonstration measures a mean direct reach of 1.68 and a mean
transitive reach of 4.72. (a) Reproduce the amplification factor. (b) For a
package whose dependency graph is a single path of $n$ modules, compute the
amplification for the module at the root and state how it scales with $n$.
(c) Explain why the measured $2.80\times$ is far below the chain value.

## ★★★ Research-oriented

**★★★7.** The demonstration's graph omits coupling through the filesystem,
where one script writes a file another reads. Specify an experiment that
estimates that hidden coupling on a real package: state the data you would
extract, the proxy for an edge, the metric you would report, and the two ways the
measurement could be wrong. A specification that could not be executed is a
failed answer.

**★★★8.** A hub module has fan-in 8. Design a split into two modules and predict,
from the demonstration's correlation between fan-in and blast radius ($0.831$),
what happens to the maximum blast radius. State the assumption your prediction
rests on, and the measurement that would falsify it.

**★★★9.** The defect model is monotone in coupling and additive over decisions.
Propose two structural modifications of the model that would make it falsifiable
on a real project, and for each state the observable that would distinguish it
from the additive form. Say what neither model can tell you about a single
module's correctness.
