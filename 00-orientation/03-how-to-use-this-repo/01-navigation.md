# Repository Navigation and File Naming Conventions

## Learning objectives

- Navigate the repository at its four levels — folder, module, lesson, and
  supporting directory — and state what each level is for.
- Decode any lesson's `id` from its path, and any path from its `id`, without
  consulting a table.
- Describe the frontmatter fields, which are required, and what each one means
  to a reader.
- Find a topic you cannot name precisely, using the reference library, the plan
  file, and text search in that order.

## Prerequisites

[Master Curriculum Map: How the 27 Folders Connect](../02-curriculum-map/01-master-map.md)
for what the folders contain. This lesson is about the mechanics of the files
themselves.

## 1. The four levels

```text
00-orientation/                          folder      (level 0: 27 of these)
├── README.md                            folder index: purpose, modules, entry points
├── 01-study-roadmap/                    module      (level 1: numbered subfolder)
│   ├── README.md                        module index: objectives, lessons, checkpoint
│   ├── 01-how-to-learn-geophysics.md    lesson      (level 2: the numbered files)
│   ├── 02-six-stages.md
│   └── ...
└── 02-curriculum-map/
    ├── README.md
    └── ...
```

| Level | What it is | Where the learner meets it |
|---|---|---|
| Folder | One thematic subject, e.g. `06-seismology` | The 27 rows of [CURRICULUM.md](../../CURRICULUM.md) |
| Module | A coherent group of lessons inside a folder, e.g. `06-seismology/02-ray-theory-and-travel-times` | Module `README.md`: objectives, prerequisites, mastery checkpoint |
| Lesson | A single teachable unit | The numbered Markdown file you read and work through |
| Supporting directory | `code/` and `exercises/` beside the lessons where they are needed | Run the code, attempt the exercises, and check your work |

Every folder and every module has a `README.md`. Those index files carry **no
frontmatter** — they are navigation and orientation, not lesson content. Lessons
carry frontmatter and pass the quality gate as described in
[Running the Link, Formula and Duplication Checks](./03-quality-gate.md).

## 2. Naming conventions

**Numeric prefixes.** Folders and modules are prefixed with a two-digit number
(`01-mathematics`, `07-linear-algebra`). Lessons are prefixed with a two-digit
number inside their module (`03-units-and-dimensional-analysis.md`). The
zero-padding is deliberate: a plain alphabetical or filesystem sort then puts
files in the intended study order, so `02-` sorts before `10-` on every
platform.

**Slugs.** The text after the number is a lowercase, hyphen-separated slug:
`05-satellite-gravimetry`, `04-contribution-workflow`. Slugs are stable
identifiers used in cross-references and in the plan file; the human-readable
title lives in the frontmatter, not in the filename.

**One lesson, one file.** A lesson is one Markdown file. Where a lesson needs
runnable code or graded problems, the convention is a `code/` or `exercises/`
directory beside it, as illustrated in the repository [README](../../README.md).

**Generated files.** [CURRICULUM.md](../../CURRICULUM.md) is generated by
`tools/build_index.py`. Do not edit it by hand; edit the plan and regenerate, or
your edit will be silently overwritten at the next run.

## 3. Decoding an `id`

Every lesson declares an `id` in its frontmatter, composed of three
zero-padded numbers joined by hyphens:

```text
06   -  02  -  04
│        │      └── lesson number inside the module
│        └───────── module number inside the folder
└────────────────── folder number
```

So `06-02-04` is the fourth lesson of the second module of the sixth folder —
`06-seismology/02-ray-theory-and-travel-times/04-...`. The rule is mechanical,
and it is the same rule the plan uses to generate paths, so an `id` and a path
are two views of the same identifier.

This matters because `id` is also the vocabulary of prerequisites: a lesson
declares `prereqs: ["00-01-01"]` meaning *how to learn geophysics*, and the
[quality gate](./03-quality-gate.md) checks that ids and titles match the plan
character for character.

## 4. Frontmatter fields

Lesson frontmatter is a small, deliberately restricted subset of YAML. The
parser supports bare scalars, quoted scalars, integers, inline lists and block
lists — nothing else, so that a malformed field fails loudly rather than being
silently skipped.

| Field | Required | Meaning |
|---|---|---|
| `id` | yes | The three-part identifier described above; must match the plan |
| `title` | yes | The human-readable title; must match the plan exactly |
| `level` | yes | One of `beginner`, `intermediate`, `advanced`, `graduate`, `doctoral`, `research` |
| `prereqs` | yes | List of lesson `id` strings assumed by this lesson |
| `tags` | yes | Short descriptive terms for search and grouping |
| `estimated_minutes` | no | Rough working time for a careful pass |
| `datasets` | no | Datasets used, with their provenance labels |
| `status` | no | Editorial state, e.g. draft or stable |
| `see_also` | no | Extra cross-references |

`level` describes the **lesson**, not the folder. The same folder contains
beginner material and research-level material, which is why the level marker in
[CURRICULUM.md](../../CURRICULUM.md) is per lesson.

## 5. What a lesson contains

Lessons share a common anatomy so that you can navigate one you have never seen:

```text
Learning objectives      what you should be able to do afterwards
Prerequisites            what you must already have
1. ... 2. ...            the teaching content, in numbered sections
Common mistakes          the specific errors this material attracts
Real-world applications  where the skill is used in practice
Further reading          bibliographic records for going deeper
Related lessons          where to go next
```

Within the numbered sections you will find derivations, worked examples, and
often a short Python demonstration. Exercises are graded ★ (essential), ★★
(working depth) and ★★★ (research depth).

## 6. Finding things you cannot name

Use three tools, in this order.

**1. The reference library.** If you have a symbol, a unit, a formula, or a
half-remembered term, start at
[26-reference-library](../../26-reference-library/README.md). It exists precisely
for the case where you do not yet know the vocabulary: glossary, symbols and
units, formula handbook, textbooks, dataset catalogue, open educational
resources.

**2. The plan file.** [`tools/curriculum_plan.py`](../../tools/curriculum_plan.py)
declares every folder, module, lesson, slug, title and level. Searching it is the
fastest way to answer "does this curriculum cover X, and where?" — and because it
is plain Python data, it can be searched and scripted like anything else.

**3. Text search.** Search the Markdown itself for a term you are confident
about. For example, to find everything mentioning magnetotellurics:

```bash
grep -ril "magnetotelluric" --include="*.md" .
```

**4. The generated index.** [CURRICULUM.md](../../CURRICULUM.md) shows coverage
and level per lesson, which is useful when you want the shape of a folder rather
than a specific lesson.

## 7. A short navigation script

The following standard-library script prints an inventory of lessons that
already exist, grouped by folder, with their levels. It is a useful habit to
keep: it tells you the real state of the repository rather than the intended
state.

```python
"""List written lessons by folder, reading frontmatter without any library."""
from pathlib import Path

ROOT = Path(__file__).resolve().parent


def frontmatter_value(text: str, key: str) -> str:
    """Return the raw value of a simple 'key: value' frontmatter line."""
    if not text.startswith("---"):
        return ""
    body = text.split("---", 2)[1]
    for line in body.splitlines():
        if line.startswith(f"{key}:"):
            return line.split(":", 1)[1].strip().strip('"')
    return ""


def main() -> None:
    for folder in sorted(p for p in ROOT.glob("[0-9][0-9]-*") if p.is_dir()):
        lessons = sorted(
            p for p in folder.rglob("[0-9][0-9]-*.md") if p.name != "README.md"
        )
        if not lessons:
            continue
        print(f"{folder.name}  ({len(lessons)} written)")
        for path in lessons:
            text = path.read_text(encoding="utf-8")
            print(f"    {frontmatter_value(text, 'id'):8} "
                  f"[{frontmatter_value(text, 'level'):12}] "
                  f"{path.relative_to(folder)}")


if __name__ == "__main__":
    main()
```

Run it from the repository root. Note what it does *not* do: it does not verify
titles against the plan, does not resolve links and does not check formula
delimiters. That is the job of
[the quality gate](./03-quality-gate.md), and keeping the two concerns separate
is why the gate can be run by a contributor without reading the whole repository.

## 8. Conventions for cross-references

- **Relative links only.** Every Markdown link in this repository is relative to
  the file containing it, e.g. `../../06-seismology/README.md`. Absolute
  filesystem paths are rejected by the quality gate because they break for every
  other reader and every other machine.
- **Link to the narrowest useful target.** A module index when the whole module
  is relevant; a specific lesson when you mean that lesson.
- **Links to planned-but-unwritten lessons are allowed** and are tracked as
  *pending* rather than broken, because the curriculum is written in batches.
- **External URLs are restricted.** Only URLs recorded in
  [`tools/verified_links.tsv`](../../tools/verified_links.tsv) may be cited,
  each with an observed HTTP status. `tools/verify_links.py` audits the Markdown
  and fails if a cited URL is not registered.
- **Datasets are labelled.** `SYNTHETIC` (generated and reproducible offline),
  `OBSERVED` (real, from an archival source with a verified URL) or
  `ILLUSTRATIVE` (hand-constructed teaching numbers). The label tells you how
  much weight the numbers can carry.

## Common mistakes

1. **Editing `CURRICULUM.md`.** It is generated; your changes are lost at the next
   build.
2. **Assuming folder numbers are difficulty levels.** They are topic groupings,
   ordered roughly by dependency; levels live in lesson frontmatter.
3. **Using absolute paths in links.** Rejected by the gate, and broken for
   everyone else.
4. **Inventing an external URL.** Only registered URLs may be cited; add the URL
   to the registry only after verifying it in a browser.
5. **Treating a module `README.md` as a lesson.** It carries no frontmatter and
   no exercise content; it is orientation.
6. **Searching by title when you only remember the topic.** Search the plan file
   or the Markdown text instead.

## Real-world applications

- **Working in someone else's repository.** Numbered, zero-padded, slug-named
  directories with index files is the dominant convention in research code and
  documentation for good reasons: sorting works, links are stable, and indexes
  answer the "where do I start" question without a guide.
- **Documentation and data catalogue work.** The frontmatter pattern here —
  machine-readable metadata in the file itself — is the same idea as dataset
  catalogue metadata, and it is what lets tooling report real coverage.
- **Onboarding.** The four-level structure is how a new team member can be given
  a folder rather than a person to shadow.
