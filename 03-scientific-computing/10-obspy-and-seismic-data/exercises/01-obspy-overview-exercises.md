# Exercises — 03-10-01 ObsPy Architecture and Data Models

Attempt these **closed-book** before opening the
[solutions](./01-obspy-overview-solutions.md). Difficulty:
★ foundational · ★★ applied · ★★★ research-oriented.

Several problems ask you to run the demo and report its output:

```
.venv/bin/python 03-scientific-computing/10-obspy-and-seismic-data/code/obspy_overview_demo.py
```

Every number you are asked to quote is printed by that script. Values marked
*measured* in the solutions are its actual output on this installation
(ObsPy 1.5.1, NumPy 2.5.4, Python 3.14.4); do not copy them without running it.

---

## ★ Foundational

**★1.** A trace has `npts = 3600` and `delta = 0.005` s. State
(a) its sampling rate in Hz, (b) its Nyquist frequency, (c) its duration in
seconds as the number of sample *intervals*, and (d) the time of its last
sample relative to `starttime`. Give units for every answer.

**★2.** The demo reports four time representations of the instant
`2024-03-15T08:30:00.123456Z`. (a) Write down all four. (b) For each, state
whether it is a count of seconds, days, or something else, and from which
epoch. (c) Explain why `julday` is not the number of days since 4713 BC.

**★3.** Answer in one sentence each:
(a) Why can `UTCDateTime` not represent the leap second `2016-12-31T23:59:60`?
(b) What does the demo measure for the interval from
`2016-12-31T23:59:59Z` to `2017-01-01T00:00:00Z`, and how many SI seconds
actually elapsed?
(c) Which of those two numbers should appear in a paper, and under what
statement of convention?

**★4.** The demo constructs a `Stream` of two traces and prints
`len(st) = 2` and `total samples = 12000`. (a) What does `len(st)` count?
(b) Does a `Stream` require its traces to be contiguous in time? (c) Name two
`Stream` methods whose behaviour depends on that question.

**★5.** For a 100 Hz trace, the demo reports that `slice` and `trim` over
`[1.0 s, 2.0 s]` both return **101** samples. Explain the arithmetic, in terms
of intervals and sample instants, and state the general rule for a window of
length $T$ at sampling rate $f_s$ when both endpoints land on samples.

## ★★ Applied

**★★6.** Write `is_consistent(trace) -> list[str]` that returns a list of
problems rather than a boolean, checking: positive sampling rate; `npts >= 2`;
`delta` equal to `1/sampling_rate` to within $10^{-9}$ relative; finite
samples; and `npts` consistent with `starttime` and `endtime` to within one
sample. Then construct a corrupted trace in which `npts` is set to 10 while
the data array still holds 6000 samples, and state which of your checks fires
and which does not. Run it and report the output.

**★★7.** The demo reports the gap between the two segments as
`10.010 s (1001 missing samples)`. Reconcile the two numbers: show that
1001 samples at 100 Hz is 10.010 s, and explain why the gap is not 10.000 s.

**★★8.** Create a `Stream` with a 4.5 s gap and produce (a) a version with the
gap preserved and (b) a version with the gap filled. Report `len(st)` and
`st[0].stats.npts` for both, and state how many samples in (b) are not
measurements. Then write two sentences a referee would accept for using (b).

**★★9.** Using only `UTCDateTime`, compute the interval between
`2016-12-31T23:00:00Z` and `2017-01-01T01:00:00Z`. Report ObsPy's answer and
the true number of SI seconds, and state the assumption under which they
differ.

**★★10.** The demo reports `trace max |amplitude| = 4.1680 counts` and
`trace RMS = 1.0130 counts`. (a) State the unit. (b) Explain what would have
to be added to the trace's metadata to convert these to metres per second.
(c) The RMS is almost exactly 1.0130, and the data were generated by
`rng.standard_normal(6000)`. Predict the RMS of a 6000-sample standard normal
sample and compare; what is the difference in units of the expected sampling
standard deviation $1/\sqrt{2n}$?

## ★★★ Research-oriented

**★★★11.** Build a `Stream` of 100 synthetic traces, each 1000 samples at
100 Hz, with the same station code. Measure and report, with units:
(a) the number of traces after `st.select(station="ABCD")`;
(b) the in-memory footprint as the sum of `trace.data.nbytes` over traces,
assuming `float64`;
(c) the same footprint if the data were `int32`;
(d) the extra footprint of the `stats` dictionaries, estimated by comparing
`st.__sizeof__()`-style measurements or by reasoning about the number of keys.
Then state the practical implication for reading a year of three-component
data at 100 Hz from a single station, and where the `Stream` model stops being
the right tool.

**★★★12.** This lesson states that ObsPy ignores leap seconds, supported by two
observations: the constructor raises on second 60, and the epoch difference
across the 2016 boundary is 1.000000 s. Design and run a **third**,
independent test. Options include reading a file whose header records a
creation time (does `obspy.read` expose it?), comparing a `UTCDateTime`
difference against a UTC-based difference computed with
`datetime.timezone.utc`, or examining whether `UTCDateTime` objects compare
across a leap boundary as POSIX times. Report exactly what you tested, the
result, and what remains unverifiable offline. State your residual
uncertainty rather than asserting a conclusion.

**★★★13.** The data model's cost is metadata re-validation. Design an
experiment that isolates that cost without quoting elapsed wall-clock time
(which is machine-dependent and therefore not a result). Suggested approach:
correlate the number of `Trace` objects with the time spent in a fixed-size
operation *relative to* a pure-NumPy baseline, expressed as a ratio measured on
the same machine in the same run. Report the ratio, state the number of traces
swept, and explain why the ratio is a more portable statement than a
millisecond count.
